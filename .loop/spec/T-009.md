## 目的

チャットパレットの行をクリックすると即座に送信されてしまい、送信前に文面を直せない。
クリックでは**チャットパレットに付随するチャット欄へ文面を入れるだけ**にし、送信は
利用者の操作に委ねる。あわせて、その入力欄の予測変換（サジェスト）が下方向に開いて
読みづらいのを、入力欄の**上側**に開くように変える。

## 受入条件

- [ ] チャットパレットの行をクリックしても発言が送信されない。クリック経路から
      チャット送信の処理（`submitFromPalette` 相当）が呼ばれなくなっている。
- [ ] クリックすると、**チャットパレットに付随するチャット欄**（チャットパレットのパネル内／
      直下にある入力欄）の値が、クリックした行のテキストで置き換わる。
      入力欄に打ちかけの文字が残っていた場合も**上書き**する。
- [ ] クリック後、その入力欄にフォーカスが移り、カーソルがテキストの末尾にある。
- [ ] **チャットパレット外のチャット欄（メインのチャット入力欄）の値・フォーカスは変わらない。**
      パレットのクリックはそちらに一切触れない。
- [ ] 予測変換のポップアップが、入力欄の**上側**（入力欄より上の領域）に開く。
      下方向に開くための位置指定が残っていない。
- [ ] 予測変換の既存の操作（候補の選択・確定・閉じる）が、位置変更のあとも同じように動く。
      候補を確定したときの入力欄への反映先が変わっていない。
- [ ] チャットパレットの保存形式（`CHAT_PALETTE_FORMAT`・localStorage の中身）と、
      パレットのテキストのパース規則（`parseChatPaletteLines`）を変えていない。
- [ ] 依存パッケージを追加していない。

## 実装メモ

コードマップから読み取れる手がかり。行番号は `docs/codemap/` 生成時点のもの。

**チャットパレット側**

- `js/chat-palette.js:102` `renderChatPalette({ container, onSend, findTokenByName })`（275行, export）
  — パレットのUIを描画する唯一の関数。行のクリックハンドラはこの中にある。
  **275行あるのでローカルLLMには渡せない**（`.loop/prompts/implement.md` 手順1参照）。
- このモジュールを import しているのは `js/main.js` **だけ**（`docs/codemap/files/js.chat-palette.md` の依存）。
  したがって `onSend` を `onPick` のような別のオプション名に変える／引数の中身を変えることは
  許可する。**その場合は `js/main.js` 側の呼び出しも必ず合わせること。**
  それ以外の export（`loadChatPaletteState` / `saveChatPaletteState` /
  `parseChatPaletteLines` / `CHAT_PALETTE_FORMAT`）のシグネチャは変えない。
- パレットの状態は localStorage にあり、部屋の共有状態（`js/game-store.js`）には入らない。
  この変更で共有状態を触る必要は無いはず。

**チャット送信側（`js/main.js`）**

- `js/main.js:1258` `submitFromPalette({ text, name, onSend })`（14行）
  — 今のパレットのクリックから呼ばれている送信経路。**クリックからは呼ばれなくする。**
  この関数自体を消すか残すかは実装役の判断でよいが、消す場合は他に呼び出しが無いことを確かめること。
- `js/main.js:1218` `submitChatText({ rawInput, character, characterName, tabId, onSent })`（37行）
  — 通常のチャット送信。こちらの挙動は変えない。

**予測変換（サジェスト）**

- `js/main.js:1337` `updateCommandInputSuggestions()`（41行）— 候補の組み立てと表示。
- `js/main.js:1331` `hideCommandInputSuggestions()`（5行）— 閉じる方。
- **ただし、これがチャットパレット付随の入力欄のものか、メインのチャット入力欄のものかは
  コードマップからは判別できない。** 実装前に、どの入力欄に対する予測変換かを確認し、
  **「チャットパレットに付随するチャット欄」のものを上側に出すこと。**
  もし両方の入力欄が同じサジェストUIを共有しているなら、両方が上側に出てよい。
- 位置の指定（`top` / `bottom` / `transform` など）はマークアップ側にある可能性が高い。
  部屋の画面は `combined_layout.html`。`css/` には `character-dialog.css` しか無いので、
  スタイルはこの HTML 内に書かれていると思われる。

**確認の観点**

- パレット付随のチャット欄とメインのチャット欄は**別物**である（利用者の指定）。
  取り違えると受入条件を満たさないので、着手前にどちらがどれかを特定すること。
