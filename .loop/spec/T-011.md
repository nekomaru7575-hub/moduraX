## 追記: 時刻の確定場所（2周目の検査を受けて）

チャットログに入る時刻は、**その action が最初に作られた1か所で確定**させ、
ローカル楽観適用・サーバーの権威適用・他クライアントへの中継適用は、
**確定済みの値をそのまま使う**こと。各機械が `Date.now()` を呼び直してはいけない。

これは `ADD_CHAT_MESSAGE`（利用者の発言）だけでなく、
**`withSystemLog` を通るシステムメッセージ**（ラウンド進行・行動済み・割り込み・入室など）にも
同じように当てはまる。経路によって扱いが違ってはならない（受入条件に明記済み）。

サーバー自身が起点の action には確定済みの時刻が無い場合がある。
そのときだけ受け取った側で補うのは構わないが、**補った値がそのまま全参加者へ配られる**
（＝各自が別々に計算しない）ようにすること。

## LOCAL TASKS

### js/main.js :: buildLogHtml

Add `time` to the first parameter's destructured fields (no default value — it must stay `undefined` when the caller's object has no `time` key). Do not add or remove any other parameter.

In the function body, build a timestamp string:
- When `time` is a finite number (epoch milliseconds), format it as local-time `HH:MM:SS` (24-hour clock, hours/minutes/seconds each zero-padded to 2 digits) using `new Date(time)`.
- In every other case (undefined, null, a string, NaN, etc.) the timestamp string must be the empty string `""`. Never substitute the current time.

Wrap a non-empty timestamp string as `<span class="log-time" style="color: #888;">TIME</span>` (where TIME is the formatted string) and add it as a new first entry in the array that builds `headerLine` (currently `[systemTag, characterTag, commentTag].filter(Boolean).join(' ')`), so it is filtered out the same way when empty and otherwise shows before the system tag. Do not change how `systemTag`, `characterTag`, `commentTag`, `detail`, `commandHtml`, or `resultHtml` are built.

### js/log-export.js :: buildEntryHtml

Add `time` to the destructured parameter (no default value — it must stay `undefined` when the caller's object has no `time` key). Do not add or remove any other parameter.

In the function body, build a timestamp string the same way:
- When `time` is a finite number (epoch milliseconds), format it as local-time `HH:MM:SS` (24-hour clock, hours/minutes/seconds each zero-padded to 2 digits) using `new Date(time)`.
- In every other case (undefined, null, a string, NaN, etc.) the timestamp string must be the empty string `""`. Never substitute the current time.

When the timestamp string is non-empty, build `timeHtml` as `<span class="log-time">TIME </span>` (TIME is the formatted string, note the trailing space inside the span). When it is empty, `timeHtml` must be the empty string `""` — do not render an empty span. Prepend `timeHtml` to the returned line, immediately before `nameHtml`, inside the same `<div class="log-line">` (i.e. the return statement becomes `` `    <div class="log-line">${timeHtml}${nameHtml}${bodyHtml}${commentHtml}</div>${detailHtml}` ``). Do not change how `bodyHtml`, `nameHtml`, `commentHtml`, or `detailHtml` are built.

## 目的

独立した2件をまとめて入れる。

1. チャットタブの**削除**と**名前変更**を、タブの設定ダイアログからできるようにする
   （今は追加と公開先の変更しかできない）。
2. チャットログの各発言に**タイムスタンプ**を持たせ、画面と書き出し HTML の両方に表示する。

## 受入条件

### タブの削除・名前変更

- [ ] タブの設定ダイアログ（`showChatTabDialog`、`mode: 'edit'`）から**タブ名を変更**でき、
      確定すると共有状態のタブ名が変わる。名前は全参加者に同期される。
- [ ] 同じダイアログから**タブを削除**できる。
- [ ] 削除を選ぶと**確認ダイアログが出る**。確認して初めて削除される。
      確認 UI は既存の `js/log-clear-dialog.js` の `showLogClearConfirmDialog({ onConfirm })` と
      同じ構え（確認を取るだけで、実際の削除は呼び出し側が行う）にする。
      既存のこの関数を流用してもよいし、同じ構えの新しい確認を作ってもよい。
- [ ] 削除すると、**そのタブのチャットログも一緒に消える**（`chatLogs` からそのタブ分が消える）。
- [ ] **既定タブ（先頭のタブ）は削除できない。** 削除の導線が出ないか、押しても削除されない。
      どのタブが既定かの判定は、実装役が既存コードから決めて `NOTES:` に書くこと。
- [ ] 削除・名前変更は**タブを追加できる人と同じ範囲の人ができる**（追加が誰でもできるなら
      削除・名前変更も誰でもできる）。GM 限定などの新しい権限判定を足さない。
- [ ] 表示中のタブを削除した場合、表示が別の存在するタブへ移り、
      「存在しないタブを表示している」状態にならない。
- [ ] タブが1本も無い状態にならない。

### タイムスタンプ

- [ ] チャットの発言（チャットログのエントリ）に時刻の情報が保存される。
      発言が作られる時点で記録し、表示のたびに現在時刻を使うようなことはしない。
- [ ] 画面のチャットログに **`HH:MM:SS`** 形式（例 `14:32:07`）で表示される。
- [ ] 「ログを保存」で書き出した HTML にも、画面と**同じ `HH:MM:SS` 形式**で表示される。
- [ ] **時刻を持たない既存のログエントリ**（この変更より前に作られたもの、および
      読み込んだ保存データに入っていたもの）を表示しても、例外にならず、
      でたらめな時刻（表示時点の現在時刻など）を出さない。時刻欄が空のまま表示されること。
- [ ] 時刻はチャット送信・システムログ・ダイスロールなど、**チャットログに入る経路すべて**で
      同じように付く（経路によって付いたり付かなかったりしない）。
- [ ] 部屋の保存データ（全データ書き出し）に時刻が含まれ、読み込むと復元される。
      新しいフィールドを増やすだけで、既存のフィールドの意味を変えない。

### 共通

- [ ] 依存パッケージを追加していない。
- [ ] 既存の公開関数（export）のシグネチャを、省略可能な引数の追加以外の形で変えていない。

## 積み残し（2026-08-09 に受入。ループ3周で解消せず）

**入室メッセージ（`ADD_ENTRY_MESSAGE`）の時刻だけ、参加者ごとにズレる。**

`server/index.js:1591` がサーバー自身の store で直接 dispatch するため、
クライアントの dispatch ラッパ（`js/net-sync.js`）を通らない。サーバーは自分用に時刻を
1回補うが、その値を `broadcastToRoom` へ渡す payload に書き戻していないので、
受け取った各クライアントが個別に `Date.now()` を計算し直す。

- 影響は「〈名前〉が入室しました」の1行のみ。`HH:MM:SS` 表示なので、
  秒の境界をまたいだときだけ1秒違って見える。
- 受入条件「チャットログに入る経路すべてで同じように付く」は**この1経路だけ未達**（15/16 met）。
- `server/index.js` を ALLOW に入れていなかったため未修正のまま受け入れた。
  厳密な時刻の一致は求められていない、という利用者の判断による。
- 直すときは `server/index.js` を ALLOW に足し、サーバーが補った時刻を
  `entryPayload` に書き戻してから `broadcastToRoom` する。**それだけで済む。**
