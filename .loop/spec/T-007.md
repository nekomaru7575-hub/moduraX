## LOCAL TASKS

## 目的

素のチャット発言が送信されたとき、部屋の全員の端末で送信音を鳴らす。
コマンドとして処理された入力では鳴らさない。
あわせて、システム音（入室音・チャット送信音）の音量スライダーを♪ダイアログに1本追加する。
この音量は**ブラウザごと**（localStorage）で、部屋の共有状態には載せない。

## 受入条件

### チャット送信音

- [ ] 送信音の URL はサーバーの環境変数 `CHAT_SEND_SOUND_URL` から読む。ハードコードしない
- [ ] 素のチャット発言が送信されたとき、**送信者を含む部屋の全員**の端末で1回鳴る。配信の作りは T-006 の入室音（サーバーが払い出した URL を ACTION の payload で運ぶ）に揃える
- [ ] 次のいずれかとして処理された入力では鳴らない: `tryHandleParameterCommand` / `tryHandleBuffCommand` / `tryHandlePhaseEndCommand` / `tryHandleAudioStopCommand` / `tryHandlePluginChatCommand` / `tryHandleOriginalTableCommand`、および BCdice が判定として**受理して結果を返した**入力
- [ ] 判定基準は「BCdice へ送ったかどうか」ではなく「**最終的に素の発言としてログに流れたかどうか**」である。BCdice が `unsupported`（コマンドとして認識できなかった）を返し、入力がそのまま平文の発言としてログに載る経路は**鳴らす**
- [ ] 次の4経路すべてで鳴る。1回の送信につき配信要求は**1回だけ**（二重に鳴らさない）
  1. チャット欄の送信ボタン押下
  2. チャットパレットのチャット欄の送信ボタン押下
  3. チャットパレットの項目クリックによる発動
  4. チャット欄でのチャットパレット候補選択
- [ ] `CHAT_SEND_SOUND_URL` が未設定または空文字のとき、クライアントは再生処理を呼ばない（`new Audio(...)` や `play()` に到達しない）

### システム音の音量

- [ ] ♪ダイアログ（`showAudioDialog`）に、システム音用の音量スライダーが**1本**増えている。既存の BGM／効果音のスライダーはそのまま
- [ ] このスライダーの値は localStorage に保存され、リロード後も復元される
- [ ] この値は**部屋の共有状態（`room.audioPlayback` / `AUDIO_CHANNELS`）に入らない**。`AUDIO_CHANNELS` に新しいチャンネルを追加しない
- [ ] 入室音（`playEntrySound`）とチャット送信音の**両方**にこの音量が掛かる
- [ ] 音量が 0 のとき、どちらの音も鳴らない
- [ ] 既存の BGM／効果音のチャンネル音量・ミュートの挙動を変えない

### 共通

- [ ] `.env` を変更しない（サーバーは `process.env` から読むだけ）
- [ ] 入室音の既存の受入条件（T-006）を壊さない

## 実装メモ

コードマップから読み取れる材料。行番号は生成時点のもの。

### 4経路の収束先

`js/main.js` に送信の入口が2つある。**4経路がこの2つに収束しているかを最初に確認すること。**

- `submitChatText({ rawInput, character = null, characterName, tabId = activeTabId, onSent })`（1213行）
- `submitFromPalette({ text, name, onSent })`（1246行）

コマンド判定はこの2関数の中で `tryHandle*Command` 群を順に試す形になっているはず。
**音を鳴らすかの判定はこの2関数の中で行い、「どの `tryHandle*` にも該当せず素の発言として送信された」経路にだけ配信要求を置く。**
呼び出し側（ボタンのイベントハンドラ）に置くと、コマンドかどうかを知らないまま鳴らすことになる。

候補選択の経路は `updateCommandInputSuggestions()`（1325行）/ `hideCommandInputSuggestions()`（1319行）の周辺。
パレット側の描画は `js/chat-palette.js` の `renderChatPalette({ container, onSend, findTokenByName })`（102行）で、
`onSend` コールバックが `js/main.js` 側から渡されている。

### 入室音の既存の作り（これに揃える）

- `server/index.js`: `const ENTRY_SOUND_URL = process.env.ENTRY_SOUND_URL || ''` を読み、
  `broadcastToRoom(entry, sender, message)`（552行付近）で ACTION の payload に URL を乗せて配信
- `js/net-sync.js`: 受信した ACTION の payload に URL があれば `playEntrySound(url)` を呼ぶだけ（判断を持たない）
- `js/audio-player.js`: `playEntrySound(url)`（98行）。`if (!url) return;` が先頭にある

送信音も同じ形にする。サーバー側で `CHAT_SEND_SOUND_URL` を読み、クライアントは運ばれた URL を鳴らすだけ。
**クライアントに `process.env` を書かない。**

### 音量

- `js/audio-player.js` の `getChannelVolume(channel)`（28行）/ `setChannelVolume(channel, value)`（34行）は
  **部屋の共有状態を読む既存の仕組み**。システム音はここに乗せない
- システム音の音量は `js/audio-player.js` に localStorage 読み書きの口を新設し、
  `playEntrySound` と送信音の再生の両方で `audio.volume` に掛ける
- localStorage のキーの付け方は `js/chat-palette.js` の `loadChatPaletteState()`（60行）/
  `saveChatPaletteState(state)`（77行）が既存の作法。これに倣う
- ♪ダイアログのスライダーは `showAudioDialog(...)`（`js/audio-dialog.js` 194行）の中に足す。
  既存のチャンネル音量スライダーと同じ見た目に揃える。CSS の追加が要るなら `css/character-dialog.css`

### 既存のミュート

`isMuted()` / `setMuted(muted)`（40・46行）が部屋共有のミュート。
システム音をこのミュートに従わせるかは実装役が決めてよい。決めた結果を `NOTES:` に書くこと。
