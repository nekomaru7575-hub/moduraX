## 目的

ステータス変更コマンドのダイスは BCdice を通っているが、通常のチャットロールと扱いが揃って
いない。(1) 3Dダイス演出が出ない、(2) ログに出目の内訳が付かない、(3) バフ/デバフコマンドは
そもそもダイス式を受け付けない。この3つを直し、**通常ロール・ステータス変更・バフ/デバフの
3経路でダイスの扱いを同じにする。**

## 受入条件

- [ ] ステータス変更コマンドのダイス経路で、`rollBCDice` の戻り値から出目配列
      （`diceValues` / rands）を受け取っている（今は `{ success, resultText }` しか
      受け取っておらず捨てている）。
- [ ] 受け取った出目で、通常のチャット送信経路（`js/main.js:783` 付近）と**同じ形の**
      3Dダイス演出の dispatch を行っている。演出に流すダイス数の上限は既存の
      `MAX_ANIMATED_DICE`（`js/dice-notation.js`）を使い、新しい上限定数を作っていない。
- [ ] ステータス変更コマンドのログに、通常ロールと同じ出目の内訳が載っている
      （`buildLogHtml` の `diceDetail` 引数に、通常経路と同じ作り方で値を渡している）。
- [ ] バフ/デバフコマンドの増減値に**ダイス式**（`1d6` `2D6` など）を書けるようになっている。
      `BUFF_COMMAND_PATTERN`（`js/main.js:1003` 付近）の増減値部分が、
      今の `([+-]?\d+(?:\.\d+)?)` からダイス式も受け付ける形に広がっている。
- [ ] バフ/デバフコマンドにダイス式を書いた場合、`rollBCDice` を通して評価し、その結果の数値を
      増減値として使っている。独自のダイスロジック（`Math.random` など）を書いていない。
- [ ] バフ/デバフコマンドのダイスでも、3Dダイス演出とログの出目の内訳が、
      ステータス変更コマンドと同じように出る（3経路で扱いが揃っている）。
- [ ] **ダイス式でない素の数値**（ステータス変更の `(10)`、バフの `+3` `-2.5` など）の既存挙動が
      変わっていない。この場合は `rollBCDice` を呼ばない。
- [ ] BCdice の呼び出しが失敗したとき（戻り値の `success` が false のとき）の扱いが、
      ステータス変更・バフの両方で同じで、ステータス変更側の既存の扱いを変えていない。
- [ ] 通常のチャットロール（`submitChatText` 経路）の挙動・ログ表示が変わっていない。
- [ ] 依存パッケージを追加していない。

## 実装メモ

行番号はコードマップ生成時点および先行調査時点のもの。ズレていたら現物に合わせること。

**ステータス変更コマンド（経路1・2を直す）**

- `js/main.js:904` `tryHandleParameterCommand(rawInput, character)`（72行）— 入口。
- `js/main.js:958` `DICE_AMOUNT_PATTERN` — 増減値がダイス式かどうかの判定。
- `js/main.js:961` `rollBCDice(store.state.room.bcdiceSystem, rawAmount)` の呼び出し。
  **ここで `{ success, resultText }` だけを分割代入しており、`diceValues` を捨てている。**
  `rollBCDice` は `js/BCdice.js` の export で、`js/main.js:3` で import 済み。
- `js/main.js:865` `parseFinalDiceNumber(resultText)`（7行）— 結果テキストから合計値を取る。
- `js/main.js:883` `applyParameterChanges({ character, targets, amount, diceResultText, command })`
  （20行）— ここでログを組んで `applyLog` に渡している（`js/main.js:908` 付近）。
- 素の数値のときは `Number(rawAmount)` に落ちる分岐がある（`js/main.js:980` 付近）。**この分岐は変えない。**

**通常のチャットロール（真似する側。挙動は変えない）**

- `js/main.js:1218` `submitChatText({ rawInput, character, characterName, tabId, onSent })`（37行）。
- `js/main.js:783` 付近 — 3Dダイス演出の dispatch。`diceValues` と `MAX_ANIMATED_DICE` を使っている。
- `js/main.js:777` 付近・`js/main.js:803` 付近 — `diceDetail`（出目の内訳テキスト）の作り方。
- 演出そのものは `js/dice-animation.js` が `js/EventBus.js` 経由で拾う（`initDiceAnimation()`）。
  変換は `js/dice-notation.js:58` `randsToNotation(rands)`、上限は同ファイル:11 `MAX_ANIMATED_DICE`。
  **`js/dice-animation.js` は ALLOW に入れていない。演出側を直す必要が出たら `NEED-ALLOW:` で戻れ。**

**バフ/デバフコマンド（経路3を広げる）**

- `js/main.js:1005` `tryHandleBuffCommand(rawInput, character)`（61行）— 入口。
- `js/main.js:1003` 付近 `BUFF_COMMAND_PATTERN` — 増減値部分が `([+-]?\d+(?:\.\d+)?)` で
  ダイス式を受け付けない。`1d6` と書くとコマンドとして認識されず素通りする。
- `js/main.js:1022` 付近 `delta = Number(rawDelta)` — 単純な数値変換のみ。

**注意点**

- `rollBCDice` は fetch を使う非同期関数。`tryHandleBuffCommand` からダイスを振るなら
  この関数を async にする必要がある。両関数はモジュール内部の関数（export ではない）なので、
  **async 化と呼び出し元での await は許可する。** ただし呼び出し元
  （`submitChatText` など）が同期を前提にしている箇所を壊さないよう、
  戻り値で「コマンドとして処理したか」を伝える既存の約束は保つこと。
- ステータス変更側が既に async 経路で動いているなら、その書き方をそのまま踏襲すること
  （新しい流儀を持ち込まない）。
- バフの増減値にダイス式を許すと、負のダイス（`-1d6` のような書き方）をどう扱うかが問題になる。
  **ステータス変更コマンド側の既存の扱いと同じにすること。** 揃えられない場合は、
  最も保守的な選択（既存挙動を壊さない方）を取り、報告の `NOTES:` に書け。
