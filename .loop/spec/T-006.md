## LOCAL TASKS

## 目的

部屋に入室したとき、既定のチャットタブ（Main）に「〈名前〉が入室しました。」を1件出す。
部屋設定で有効/無効を切り替えられ、既定は有効。あわせて入室音を鳴らす仕組みだけ作る
（音源はまだ無いので、URL が設定されていなければ鳴らさない）。

## 受入条件

- [ ] 部屋の状態に「入室メッセージを出すか」の真偽フラグが1つ増えている。`createInitialGameState`（`js/game-store.js` 1935行）が返す初期状態で、この値が **true**（有効）である
- [ ] 既存の「イニシアチブプロセスを挟む」設定と**同じダイアログ／同じ領域**に、このフラグを切り替えるチェックボックスが1つ増えている。新しいダイアログは作らない
- [ ] そのチェックボックスの操作可否は、既存の「イニシアチブプロセスを挟む」設定と同じ権限判定を通る（独自の権限判定を新設しない）
- [ ] サーバーは identify（名乗り）完了時に、**その participantId の接続が同じ部屋にまだ1つも無い場合に限り**、既定のチャットタブへ入室メッセージを1件追加する。既に接続がある状態で increment された2本目以降の接続では追加しない
- [ ] 追加されるメッセージ本文は `〈名前〉が入室しました。` である
- [ ] 名前は入室者のニックネーム。未設定または空文字（空白のみを含む）の場合は `ゲスト` を使う
- [ ] フラグが false の部屋では、入室してもメッセージが追加されない
- [ ] 入室音の URL はサーバーの環境変数 `ENTRY_SOUND_URL` から読む。ハードコードしない
- [ ] `ENTRY_SOUND_URL` が未設定または空文字のとき、クライアントは音の再生処理を呼ばない（`new Audio(...)` や `play()` に到達しない）
- [ ] `ENTRY_SOUND_URL` に値があるとき、入室メッセージが表示された端末で1回だけ再生を試みる
- [ ] `.env` を変更しない（サーバーは `process.env` から読むだけ）
- [ ] 既存の再接続・タブ複数開きで、入室メッセージが増え続けない

## 実装メモ

コードマップから読み取れる材料。行番号は生成時点のもの。

### 状態とシステムログ

- `js/game-store.js`
  - `withSystemLog(chatLogs, text)`（260行、非export）— システムメッセージをログへ入れる既存の関数。これを使う
  - `usesInitiativeProcess(state)`（136行）— **既存の「ルーム単位・全員共通」設定の読み取り口**。新しいフラグはこれと同じ置き方・同じ既定値の与え方に揃える。UI の場所もここから辿れる
  - `createInitialGameState(...)`（1935行）— 初期状態。ここに既定値 true を入れる
  - `ImmutableStore`（509行、class）— 状態変更はすべてこのクラスのメソッド経由。`dispatch` は 1000 行超あるので、追加する分岐は最小限にする
- `js/state-import.js` の `adoptImportedState` — 古い保存データにフラグが無い場合の既定値をここで補う必要があるか確認する

### 入室の検出（サーバー）

- `server/index.js`
  - `broadcastToRoom(entry, sender, message)`（552行）— 部屋の全接続へ送る既存関数
  - `getOrLoadRoom(roomId)`（457行）— 部屋のエントリ（接続の集合を持つ）を取る
  - `verifyIdentity(participantId, authToken)`（117行）— identify の検証
  - 「その participantId の接続がまだ無いか」は、identify を受けた時点で **その接続自身を数に入れる前に**判定すること

### 名前がサーバーに届いていない可能性

`js/net-sync.js` の `sendIdentify(participantId, authToken)`（218行）は**名前を送っていない**。
ニックネームは `js/local-identity.js` の `getNickname()` がクライアント側で持っている。

サーバーが名前を知らない場合は、**identify のペイロードに名前を足してよい**
（`js/net-sync.js` と `server/index.js` の両方が ALLOW にある）。サーバー側で
空文字・空白のみを `ゲスト` に丸めること（クライアントの丸めを信用しない）。

### 入室音

- 環境変数名は `ENTRY_SOUND_URL` で固定。`.env` は編集しない（`server/dev-local.js` が dotenv を読む）
- サーバーだけが `process.env` を読み、クライアントへは WebSocket のメッセージか既存の設定取得経路で渡す。**クライアントに `process.env` を書かない**
- 再生は `js/audio-player.js` に口を足すか、`js/main.js` に閉じるかを実装役が選んでよい。
  既存の `triggerAudioPhrase(text)`（`js/main.js` 1125行）が「発言をきっかけに音を鳴らす」既存の配線なので、まずこれを見ること
- チャンネル音量・ミュートを既存の仕組みに乗せるかは任意。乗せない場合は理由を `NOTES:` に書く

### UI

`combined_layout.html` に既存のイニシアチブ設定のチェックボックスがあるはず。
その隣に1つ足す。CSS の追加が要るなら `css/character-dialog.css`。

## 禁止事項

- ALLOW リスト外のファイルを変更しない
- `.env` を変更しない
- 依存パッケージを追加しない（package.json / package-lock.json を触らない）
- 既存の公開関数のシグネチャを変更しない（`sendIdentify` への引数追加は例外として許可する）
- 新しいダイアログ・新しい権限判定を作らない
- git commit / git push を実行しない
- 動作に関係ないリファクタや整形をしない
