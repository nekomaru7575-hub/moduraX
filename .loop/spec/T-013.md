## 目的

誰かが発言を書いている最中であることが、他の参加者から分からない。
**メインのチャット入力欄に文字が入っている参加者の名前を、チャット欄の右下に一覧で表示する。**

## 受入条件

### 何を出すか

- [ ] メインのチャット入力欄が**空でない**参加者の名前が、チャット欄の**右下**に一覧で表示される。
- [ ] **チャットパレットに付随する入力欄は対象外。** そこに文字を入れても記入中にならない。
      （T-009 で確認済み: メインは `combined_layout.html` の `#commandInput`、
      パレット付随は `js/chat-palette.js` が動的に作る `.chat-palette-send-input`）
- [ ] **自分自身は一覧に出ない**（「他ユーザの」記入中表示なので）。
- [ ] 誰も記入中でないときは、一覧の領域が表示されない（空の枠が残らない）。
- [ ] 表示する名前は、**既存の参加者名の出し方に合わせる**（入室メッセージや参加者一覧で
      使っている表記と同じにする）。名前未設定の参加者の扱いも既存の慣習に従うこと。
      何に合わせたかを `NOTES:` に書くこと。

### いつ送り、いつ消えるか

- [ ] 「記入中」の通知をサーバーへ送るのは、入力欄が**空から非空になった瞬間**と
      **非空から空になった瞬間**の2回だけ。打鍵のたびには送らない。
- [ ] 発言を送信して入力欄が空になったとき、その参加者は一覧から消える。
- [ ] 参加者が**切断・退室したとき**（タブを閉じる、通信が切れる等）、
      その参加者は一覧から消える。記入中のまま残らない。
- [ ] 自分が再接続したとき、**他の参加者の記入中の状態が正しく見える**か、
      少なくとも古い情報が残り続けない。どちらにしたかを `NOTES:` に書くこと。

### どこに置くか（重要）

- [ ] 記入中の状態は**部屋の共有状態（`js/game-store.js` の state）に入れない。**
      揮発的な情報なので、**部屋の保存データ（全データ書き出し）に含まれてはいけない。**
      チャットログにも残さない。
- [ ] したがって `js/game-store.js` は変更しない（ALLOW に入っていない）。
      WebSocket の**専用のメッセージ種別**として、既存の状態同期とは別に扱うこと。
- [ ] 既存の WebSocket メッセージ（ACTION による状態同期、入室・音の要求など）の
      挙動が変わっていない。未知のメッセージ種別を受け取った側が壊れないこと。

### 共通

- [ ] 依存パッケージを追加していない。
- [ ] 既存の公開関数（export）のシグネチャを、省略可能な引数の追加以外の形で変えていない。

## 実装の記録（受入条件が `NOTES:` への記載を求めていた3点）

実装役の報告をここへ転記した。以後の検査・改修はこれを前提にしてよい。

**(1) 参加者名の表記を何に合わせたか**

入室メッセージ（`ADD_ENTRY_MESSAGE`）と同じ規則に合わせた。IDENTIFY で届く `message.name` を
trim し、空なら「ゲスト」に丸める処理を `ws.participantName` として一本化し、
入室メッセージと記入中一覧の両方でこの値を使う（`server/index.js` 1591-1595 行付近）。

**(2) 再接続時に他の参加者の記入中がどう見えるか**

記入中はサーバーの `entry.typing`（部屋ごとのメモリ上の Map。`entry.store` の外なので
保存データに入らない）が権威。`admit()` で INIT 送信の直後に、**誰も記入中でなくても必ず**
`TYPING_USERS` のスナップショットを送るため、再接続直後の画面は常に現況で上書きされ、
古い情報が残らない。自分が記入中のまま再接続した場合は、サーバー側の記録が接続ごとに
失われるので、`js/main.js` の `NET_INITIALIZED` 購読で自分の `TYPING_START` を送り直す。

**(3) 入力イベントを相乗りさせたか、新設したか**

新設していない。既存の `commandInput` の `input` リスナー
（`updateCommandInputSuggestions` を呼んでいた箇所）に相乗りし、同じコールバックの中で
`updateTypingIndicatorState()` も呼ぶ。ただし `value` への代入は `input` を発火しないため、
送信後のクリア（`onSent`）でだけ明示的に呼んでいる。

**その他、実装役が判断した点**

- チャットパレット付随の入力欄は元々 `commandInput` の外にあるので、
  何も変更せずに「対象外」の条件を満たしている。
- 未確認（IDENTIFY 未成功）のゲストは記入中一覧の対象外にした。
  `ADD_ENTRY_MESSAGE` と同じ基準。名前と ID が安定しないため。
- 同一参加者が複数のタブを開いている場合、片方のタブで入力をやめても、
  もう一方がまだ記入中なら一覧から消えない（`TYPING_STOP` と `close` の両方で
  `ws.isTyping` を見て判定している）。
- 表示位置は、チャット入力欄（`chat-input-row`）の直下・右寄せのテキストとして「右下」を実現した。
