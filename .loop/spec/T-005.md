## 目的

DX3 の能力・技能表示ボックスについて、次の3点を直す。

1. 「実行」「判定をコピー」「閉じる」を横1行に並べる
2. 「判定をコピー」の対象を、定義済みの全技能＋ユーザーが追加した技能に広げる（技能値が未設定でも出す）
3. 判定コマンドの末尾に、半角スペース区切りで `<技能名>判定` のラベルを付ける

## 受入条件

- [ ] 「実行」「判定をコピー」「閉じる」の3ボタンが**同一の親要素の中に横並び**で配置されている（縦積みにならない）
- [ ] 3ボタンのいずれにも `width: 100%` 相当が効いていない。必要なら `css/character-dialog.css` に横並び用の指定を足してよい
- [ ] コピー対象は `DX3_ABILITY_SKILL_GROUPS` に定義されている全技能と、ユーザーが追加した技能の**両方**である
- [ ] **技能値が未設定（0・空・未定義）の技能も行を出す。** T-004 で入れた「値が設定されている技能だけ」の除外は取り除く
- [ ] 判定コマンドの末尾が「半角スペース + 技能名 + `判定`」で終わる。丸括弧・二重山括弧などの装飾文字を付けない（技能名が `白兵` なら末尾は ` 白兵判定`）
- [ ] このラベルは「実行」ボタンが送る判定文にも同じ形式で付く（下の実装メモを参照）
- [ ] 判定コマンドの書式を生成する経路は1つのままで、「実行」と「コピー」で書式が分岐していない
- [ ] 能力値単体の判定（技能を伴わない素の能力値判定）の行は、今回も含めない
- [ ] 技能が1件も無い場合に例外を投げない

## 実装メモ

- 3点目のラベルは、**「実行」とコピーの両方に付ける**方針とする。T-004 で `buildDX3CheckCommand()` に書式生成を集約してあるので、そこに1箇所足せば両方に効くはず。既存の書式を2つに分岐させないこと。
  <!-- 依頼文では「判定文の後」とだけ指定されており、コピー限定とは書かれていなかったため、
       共通の書式として扱う。ユーザー承認済み。 -->
- ユーザーは定義済み技能を「8技能」と呼んでいる。`DX3_ABILITY_SKILL_GROUPS` から数えた定義済み技能の件数がこれと食い違う場合は、勝手に合わせずに `NOTES:` で実際の件数を報告すること。
- 「追加された技能」がどう保持されているか（可変スロット・自由入力欄など）は自分で確認する。T-004 の実装では固定技能と可変スロット技能の両方を見ていたので、その処理が流用できる可能性がある。
- 未設定の技能を出す場合の技能値の扱い（`0` として出すのか、既存の `Number(value) || 0` の結果をそのまま使うのか）は、既存の判定コマンド生成に合わせる。**新しい規則を作らない。**
- 追加技能の技能名が空文字のものは、ラベルが `判定` だけになってしまうため行を出さない。
- 「閉じる」ボタンが現在どの要素にあるかを確認してから動かすこと。閉じる動作そのものは変えない。

## 禁止事項

- ALLOW リスト外のファイルを変更しない
- 依存パッケージを追加しない（package.json / package-lock.json を触らない）
- 既存の公開関数のシグネチャを変更しない
- 「実行」ボタンの判定処理そのもの（ダイス送信先・値の計算）を変更しない。変えるのは末尾ラベルだけ
- git commit / git push を実行しない
- 動作に関係ないリファクタや整形をしない
