# 変更したときに一緒に直す場所

直し忘れると「手元では動くのに本番だけ壊れる」「公開したのに表示義務を満たしていない」
といった、後から見つけにくい形で効いてくるものを集めた。

種類ごとに引く。該当する節だけ見ればよい。

---

## 毎回（画面が変わる変更をしたら）

- **`release-notes.html`** — 版の `<section>` を一番上に足す。並び順は手で保つ方式。
  何を載せて何を載せないかの決めごとは、そのファイルの冒頭コメントにある。
  画面が変わらない変更（リファクタ・依存更新）は**載せない**。
- **`js/help/help-content.js`** — 部屋の中の「？ヘルプ」。`CORE_HELP` か `PLUGIN_HELP`。
  操作が増えたのにヘルプが古いと、テスターの報告が「不具合」として返ってくる。

---

## プラグイン（対応システム）を足す

コードは1ファイル＋1行で済むが、**権利表示が3か所ある**のを忘れやすい。

1. `js/parameters/<id>.js` を作る
2. **`js/parameters/registry.js`** — `import` 1行と `PLUGINS` に1行
3. **`about.html`** の「5. 対応システムの権利表示」に権利表示を足す
   - 6社合同ガイドラインの対象作品か、リスト外かで置く場所が違う
   - 対象かどうかは https://www.arclight.co.jp/trpg-rights/ の二次創作管理製品名リストで確認
4. **`index.html`** のフッター（`.footer-rights`）の作品名リスト
5. **`NOTICE`** の「5. ゲームシステム由来の表データ」の作品一覧
6. **`README.md`** の「対応済みのプラグイン」
7. `js/help/help-content.js` の `PLUGIN_HELP`

表データを持つ場合はさらに:

- BCDice に同じ表があるなら、そこから取って **`NOTICE` の対応表**に1行足し、
  ソース側のコメントにも出所を書く（出所をたどれるようにするためと、
  書き起こしの誤りを防ぐため。権利の許諾を意味するものではない）
- BCDice に無いなら、**その旨をコメントに書く**。黙って自分で書き起こさない

スタンプを持つ場合:

- 画像は `image/stamps/<プラグインID>/` へ。**フォルダ名はプラグインIDそのまま**。
  小文字に直したりしないこと（Windowsは大文字小文字を区別しないので手元では正しく見え、
  本番のLinuxだけ404になる。実際に起きた事故）
- 記述子に `stamps: [{ id, label, file }]`
- **`NOTICE` のスタンプの節**に出所を書く（自作か、誰の何か）

## ルート直下にページ（HTML）を足す

- **`server/index.js` の `PUBLIC_FILES`** — ここに足さないと**404**。配信は許可リスト方式
- **`js/site-nav.js`** — `PAGES` に1行と `currentPageId()` に1行
- ページ側に `<button id="siteMenuBtn" class="app-menu-btn">` と
  `<script type="module" src="/js/site-nav.js">`
- `<link rel="stylesheet" href="/css/tokens.css">`
- **インライン `<script>` は動かない**（CSP `script-src 'self'`）。`<style>` は可
- `README.md` の「画面になるHTML」の表

---

## 環境変数を足す

- **`.env.example`** — 名前と役割。値は空のまま
- **本番の秘密なら `server/dev-local.js` の `PRODUCTION_KEYS`**
  ここに足さないと、`npm run dev` が**本番のデータを読み書きする**。
  検証のつもりで本番の部屋を壊した事故がこれ
- 必須のものなら `README.md` の「必要なもの」

---

## npm の依存を足す

- `package.json`（`npm install` で入る）
- **`NOTICE` の「2. npmの依存」** — 著作権表示。MITもBSDも表示の保持が配布の条件
- **`README.md` の「本番依存は5つ」という数字**

---

## vendor/ にライブラリを足す

- `vendor/<name>/` に実体と **LICENSE を同梱**
- **`NOTICE` の「1. 同梱しているライブラリ」**
  - ビルド済みのものは**中に取り込まれている依存も書く**。
    cannon-es はバンドルの過程で著作権表示が消えていて、後から気づいて足した
- 新しいディレクトリを作るなら `server/index.js` の `PUBLIC_DIRS`

---

## 画像を足す

- **`NOTICE` に出所を書く。** 自作か、誰の何か、どの条件で使えるのか。
  **出所を空けたまま増やさない**（後から調べるのは、増えてからでは手遅れになる）
- MITの対象にできるのは自作のものだけ
- **フリー素材・ファンキットはリポジトリに入れない。** 入れた時点で「使用」ではなく
  「再配布」になる。外部の置き場（`ASSET_BASE_URL`）へ置き、`.gitignore` で塞ぐ。
  置き場が未設定の環境では出ない作りになっている（`js/asset-base.js`）。
  素材の許諾を持たない人に出ないのは、欠落ではなく正しい挙動
- PWAのアイコンなら `manifest.webmanifest` と、必要なら `sw.js` の `PRECACHE_URLS`
- 権利者指定のクレジットが「当WEBサイトは〜」の形なら、
  NOTICEだけでなく **`about.html` にも掲示**する（画面に出す前提の文面のため）

## API を足す・変える

- `server/index.js` のルーティング
- **`RATE_LIMITS`**（`server/index.js` 内）— 認証不要の入口は必ず数える。
  全部屋を1プロセスで受けているので、1か所の取りこぼしが全体を落とす
- **`/security-attack-test` を通す**

---

## 色・書体を変える

- **`css/tokens.css` だけ。** 各CSSに生の `#xxx` を書かない。
  同じ役割の灰色が微妙に違う値で散らばって、変更が数十箇所の書き換えになった経緯がある

---

## about.html を触ったら

- **「最終更新」の日付**。ページ自身が「変更したら更新する」と書いている

---

## 配信・キャッシュ・Service Worker を触ったら

- `sw.js` の **`CACHE_VERSION`** を上げる（古いキャッシュが activate で捨てられる）
- **`/security-attack-test` を通す**

---

## セキュリティに関わるところを触ったら

静的配信・CSP・レート制限・WebSocket・アップロード・取り込みJSON・チャットの描画。

- **`/security-attack-test` を通す。** 「1行足しただけ」で飛ばさない。
  守りを入れた結果ふつうの操作が壊れる事故が繰り返し起きている領域

## コードマップ

`docs/codemap/` は自動生成。表を手で直しても次の生成で消える。
説明を良くしたいときは**コード側のコメント**を直す。

```bash
node tools/codemap.mjs
```

`--check` を付けると、書かずに「散文が要更新のファイル」だけ報告する。
`--accept <path>` は散文を書き直した印を付ける。
