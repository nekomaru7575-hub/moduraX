## 目的

「部屋の全データ保存」で書き出したファイルを読み込むと、保存した利用者のバックヤードに
入れてあったコマが誰のバックヤードにも現れず、事実上失われる。保存時に「保存した利用者の
バックヤードにいたコマ」をファイルへ記録し、読み込み時にその全部を「読み込んだ利用者の
バックヤード」へ入れる。

## 受入条件

- [ ] 保存データ（`exportStateToFile()` が書き出す JSON）に、保存した利用者のバックヤードに
      いたコマを特定できる情報が新しく載っている。載せる対象は保存した利用者自身の
      バックヤードのコマだけで、盤面上のコマと他の利用者のバックヤードのコマは含めない。
- [ ] 読み込み後の状態に対して `listMyBackyardTokens(state)`（`js/character-panel.js`）を
      読み込んだ利用者の ID で評価すると、保存データに記録された全コマが返る。
      バックヤードの判定条件（所有者・盤面に出ているかのフィールド）を変えた場合は、
      保存・読み込み・表示の3か所すべてで同じ判定を使うこと。
- [ ] 保存データに記録されたコマは、読み込み後に盤面へ出ない（バックヤードに入るだけ）。
- [ ] 保存データに記録されなかったコマ（盤面上のコマ）の所有者・座標は読み込みで変わらない。
- [ ] 新しい情報を持たない**既存の保存ファイル**を読み込んでも例外にならず、
      これまでと同じ結果になる（新フィールドが無い / 空配列 / 未知のコマ ID を含む場合の
      いずれでも落ちない）。
- [ ] `adoptImportedState()` の既存の呼び出し側（`server/index.js`）の挙動が変わらない。
      引数を増やす場合は省略時の既定値を現状の挙動と同じにすること。
- [ ] 既存の公開関数のシグネチャを、省略可能な引数の追加以外の形で変えていない。
